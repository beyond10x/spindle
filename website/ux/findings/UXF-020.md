# UXF-020: the keyboard's way back to the navbar runs through the page

R-02's stacked tables (UXF-009) let the pointer reader reach the request-log row on a phone in 14
actions. The keyboard reader does the same steps, but each trip to a navbar control after the
menu closes starts from inside the article: Tab walks every link, anchor and scrollable code
block below the reading position, scrolls the page with it, and reaches the field or the Close
button only after wrapping around. On the 25,000 px CLI reference that is 279 Tabs in one play,
and the page is left near its foot, below the answer.

Sessions: request-log-size 390x844 keyboard, both themes (not reached); the probe reproduces the
focus start after the menu closes.

One line: return focus to the menu's toggle button when the phone menu closes, so the next Tab
starts in the navbar.

Cost M: the shared theme's navbar (`@beyond10x/docs-system` or a swizzled Docusaurus component).
