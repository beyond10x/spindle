# UXF-021: the search field takes focus back

The navbar's search loads its index on the field's first focus. A keyboard reader tabs through the
field on the way to the sidebar, and that focus starts the load. When the index arrives, the
plugin focuses the field again, wherever the reader is: the next Enter lands in the search field,
or focus moves between the Tab that reached a link and the Enter that should follow it. Gate 5
requires that focus never moves away from where the reader put it.

The gate saw it only on a loaded host, where the index takes longer than the Tabs from the field
to the link, so it failed one play in about 60 and a different play each run.

One line: drop a focus call on the search field made outside a user's input event while the field
does not have focus.

Cost S: one client module.

## Closed

`website/src/client/search-focus.ts`: the field's focus method ignores a call made outside a user's
input event while focus is elsewhere (the index load finishes in a worker's message event); a focus
from a key, pointer or touch event, such as the plugin's keyboard shortcut, still goes through.
The asset holds the index request until the reader has tabbed one control past the field, then
releases it: red on the site without the module (3 of 3), green with it (5 of 5).
