# UXF-024: the first search hit for the request log does not hold its size

A reader who asks how many request records a run keeps types those words. The search offers two
hits. The first, with "requests" in its snippet, opens the Observe section on the request log.
That section describes what each record holds and how long its fields may be, but not how many
records the log keeps or the flag that sets it, and it links nowhere. The hit that opens the right
row is second, under a snippet from another sentence of the run section.

Sessions: request-log-size, all 8 plays, step 6; the readers then try "The observe API and UI",
the design link and the docs index and stop there.

One line: in the Observe section, state that the log keeps the last 256 records and link
`--observe-requests` to its CLI row.

Cost S: one sentence and one link in `docs/concepts/observe.md`.

Duplicate of UXF-022, found by the heuristic review of R-03 independently of the measure; closed by the same change (R-03 C2).
