# UXF-009: the meaning column of every reference table is off screen on a phone

At 390 px a table keeps its desktop column widths inside a horizontal scroll box. The first one
or two columns fill the width, so the column that answers the question (what an option does,
what a status means, what a component accepts) starts past the right edge. On the CLI reference
the reader sees a list of flags with "no" beside each and blank space where the meaning is
(shot `review-cli-observe-row--390x844--*.png`). The `observe` task's truth is in such a cell.

Sessions: all 390x844 page checks of docs, concepts-components-and-bindings, concepts-observe,
examples-rally, reference-cli and status (12 of 24); task observe at 390x844 (4 plays).

One line: on narrow screens, show each table row as a stacked label and value block.

Cost M: a table layout change in the shared theme, every generated table included.

## Closed in R-02

C1: `src/rehype/table-labels.ts` labels each body cell with its column header at build; below 997 px such a table shows each row as label and value pairs (`src/css/custom.css`). The asset ran red on `.out/R-02-build` (2 failed) and green after; the four known-failing marks of `observe` and `topology` at 390x844 are removed.
