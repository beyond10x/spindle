# UXF-023: inline code in table cells turns into code blocks

`src/rehype/code-breaks.ts` puts a `<wbr>` after each `/` of code in a table cell. The theme's MDX
code component renders a code element inline only when all of its children are plain text, so
every such span becomes a standalone, focusable code block. That splits the CLI reference's
`--observe` row into nine stacked pieces, 1,474 px tall at 1280x800. The sidebar link "run
--observe" lands on that row at 177 px, and the next row, `--observe-requests` with "How many
request records", is 1.8 screens further down. No play scrolls there. Each play goes to the
search, which leads off to Observe (UXF-024).

The same blocks add 41 Tab stops across five pages, and keyboard plays that pass the CLI
reference pay for them.

Sessions: request-log-size, all 8 plays (pointer and keyboard, both gating viewports and themes),
not reached; observe and topology still reach their answer, which is the row's first line.

One line: break paths without an element child (a zero-width space in the text, or CSS
`overflow-wrap` on code in cells), so the span stays inline.

Cost S: one rehype plugin and its test.

R-03: a fix was built and taken out. `src/theme/MDXComponents.tsx` rendered code whose children are text and `<wbr>` as inline code: 54 code blocks in cells of the CLI reference and Observe went to 0, and the `--observe` row went from 1,474 px to under 800 px. It made the L3 play `environment` at 390x844 flaky on the click path from the search: an A/B on one host load, 4 repeats per theme, passed 8 of 8 without it and 6 of 8 with it; over all runs of the environment plays at 390x844, 8 of 26 failed with it and 1 of 20 without it (that one at a host load of 118). The direct load of the same URL landed identically 16 of 16 times. Diagnose before the next attempt.
