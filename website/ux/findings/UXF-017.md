# UXF-017: search finds the section, not the row

R-01 added the offline search (UXF-001) and anchors on every option row (UXF-013). The two do not
meet: the search plugin indexes by heading, so every answer that lives in a table cell (an option of
the CLI reference, a row of Status) is reported as its section. The R-02 phone operator types the
words of the answer, "request records", and gets one hit whose snippet is an unrelated sentence of
the run section; it opens the `run` heading, and the row is six screens further down at 1280 px and
eight on a phone, where its meaning cell is also off screen (UXF-009). A reader who trusts the
search lands on the stdin format of `run` and has no cue that the answer is below.

Sessions: request-log-size at 390x844, 4 plays (not reached; 2 pointer plays used the search);
the probe reproduces it at all four gating viewport and theme pairs.

One line: index each option row as its own search entry that opens the row anchor.

Cost M: an index step for table rows beside the plugin's heading index, generated pages included.

## Closed in R-02

C2: `src/client/search-row.ts`. The index still holds one entry per heading; a page opened from the search (`?_highlight=` words) moves on to the anchored row that holds the words as typed, else each word, in the hit's section first, and the URL takes that row's anchor. The asset ran red on `.out/R-02-build` (2 failed) and green after.
