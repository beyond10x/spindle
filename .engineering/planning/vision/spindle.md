# Spindle

## Outcome

An ESS specification runs as it is written. Spindle loads the compiled model, derives the
capabilities it needs, binds them to the implementations an environment provides, and executes
the model's commands, guards, events and bindings. Nothing is generated per application.

## Objectives

- **O1 — the specification is the program.** A change to a specification changes the running
  system after a reload, with no generated code in between.
- **O2 — technicals stay in the runtime.** A specification names no store, protocol or queue. The
  same specification runs in two environments that differ only in their environment documents.
- **O3 — admission is explicit.** A deployment either binds every required capability or is
  refused with every missing capability named.
- **O4 — one component per isolation unit.** Each component of a system can run in its own
  process or microVM, joined by channels the environment provides.

## Out of scope

- The `service-sdk` repository and anything generated by it.
- Authoring capability lists by hand.
